AULA 2

Migrations: construindo o banco

Uma migration é o histórico versionado da estrutura do banco de dados.

AULA 2 • OBJETIVOS

O que é uma migration?

Sem migrations

“Execute esse SQL aí e torça para todos terem a mesma tabela.”

Difícil de reproduzir

Com migrations

A estrutura vira código, entra no projeto e pode ser executada por toda a turma.

Versionável e repetível

Migration não guarda os registros. Ela descreve como criar ou alterar as tabelas.

AULA 2 • ANATOMIA

Os métodos up() e down()

return new class extends Migration
{
    public function up(): void
    {
        Schema::create('candidatos', function (Blueprint $table) {
            $table->id();
            $table->string('nome');
            $table->timestamps();
        });
    }

    public function down(): void
    {
        Schema::dropIfExists('candidatos');
    }
};

up()
Aplica a mudança.

down()
Desfaz a mudança.

AULA 2 • EXEMPLO REAL

Criando a tabela de candidatos

Schema::create('candidatos', function (Blueprint $table) {
    $table->id();
    $table->string('nome');
    $table->string('numero', 2)->unique();
    $table->string('partido', 80);
    $table->string('foto')->nullable();
    $table->boolean('ativo')->default(true);
    $table->timestamps();
});
unique não repetenullable é opcionaldefault define valor inicial
AULA 2 • RELAÇÃO NO BANCO

Chave estrangeira em votos

$table->foreignId('candidato_id')
      ->nullable()
      ->constrained('candidatos')
      ->nullOnDelete();

Por que nullable()?

Votos brancos e nulos não possuem candidato.

Por que nullOnDelete()?

Se o candidato for removido, o voto permanece, mas perde a referência.

No nosso controller, candidatos com votos não podem ser excluídos — uma segunda proteção.

AULA 3

Models e Eloquent ORM

O Model transforma linhas do banco em objetos PHP que conseguimos consultar e modificar.

AULA 3 • CONCEITO

Uma linha vira um objeto

candidatosid: 1nome: Ana Silvanumero: 12
⇄ Eloquent ⇄

ORM significa Mapeamento Objeto-Relacional: objetos PHP conversam com tabelas relacionais.

AULA 3 • MODEL REAL

Conhecendo o Model Candidato

class Candidato extends Model
{
    use HasFactory;

    protected $table = 'candidatos';

    protected $fillable = [
        'nome', 'numero', 'partido', 'foto', 'ativo',
    ];

    protected function casts(): array
    {
        return ['ativo' => 'boolean'];
    }
}
$table escolhe a tabela$fillable permite preenchimentocasts converte tipos
AULA 3 • SEGURANÇA

Por que existe $fillable?

Permitido

Candidato::create([
  'nome' => 'Ana',
  'numero' => '12',
  'partido' => 'Aprender',
  'ativo' => true,
]);

Ignorado/bloqueado

Candidato::create([
  'id' => 999,
  'administrador' => true,
]);

Somente os campos declarados podem ser preenchidos em massa.

Relacionamentos entre Models

Um candidato pode receber muitos votos; um voto pode pertencer a um candidato.

AULA 4 • MAPA

Um voto branco pertence a algum candidato? Não — por isso a chave estrangeira aceita nulo.
AULA 4 • CÓDIGO

Os dois lados da relação

Candidato.php

public function votos(): HasMany
{
    return $this->hasMany(
        Voto::class,
        'candidato_id'
    );
}

Voto.php

public function candidato(): BelongsTo
{
    return $this->belongsTo(
        Candidato::class,
        'candidato_id'
    );
}
AULA 4 • CONSULTAS

Consultando através das relações

// Todos os votos de um candidato
$votos = $candidato->votos;

// Quantidade sem carregar todos os registros
$quantidade = $candidato->votos()->count();

// Candidato relacionado ao voto
$nome = $voto->candidato?->nome;

// Trazer candidatos já com sua contagem
$candidatos = Candidato::withCount('votos')->get();

O operador ?-> é importante: votos brancos e nulos não possuem candidato.
